# RISKS AND CONSTRAINTS

## Технические риски

## 1) Destructive side effects
- Многие этапы делают `move/delete/rename/upload`.
- Ошибка в оркестрации может приводить к потере данных или некорректной публикации.

## 2) Внешние API и квоты
- Gemini/ElevenLabs/ComfyUI/RunPod/S3/Supabase зависят от сетевой стабильности и лимитов.
- Возможны фейлы long-running задач и частично завершенные прогоны.

## 3) Файловая связность вместо API-контрактов
- Текущая интеграция строится на структуре папок и именах файлов.
- Любое неосторожное изменение структуры ломает соседние модули.

## 4) Параллельность и гонки
- Параллельные воркеры и claim-файлы могут конфликтовать при ручном вмешательстве.
- Нужны жесткие правила владения story-item в run-time.

## 5) Runtime state fragility
- `user_data*`, progress/state/log-файлы критичны для устойчивости.
- Повреждение или рассинхронизация state ведет к дублям/пропускам.

## 6) Секреты и чувствительные данные
- Ключи/аккаунты/локальные профили не должны утекать в логи и коммиты.
- Оркестратор не должен печатать секреты в stdout.

## Организационные риски

## 1) Неявные ручные этапы
- Часть реального процесса может быть “знанием оператора”, а не кодом.
- Без фиксации таких шагов roadmap будет неполным.

## 2) Ложный рефакторинг
- Риск “улучшить” рабочие legacy-модули до фиксации контрактов.
- Это ломает производственный темп.

## 3) Нечеткие критерии готовности
- Без формальных DoD для этапов сложно масштабировать поток и контролировать качество.

## Ограничения проекта (must follow)

- Не переписывать рабочие модули на первом этапе.
- Не менять Gemini-промпты без отдельной команды.
- Не ломать старую файловую структуру.
- Не объединять похожие ветки до полного контракта и аудита.
- Любые новые шаги — только как безопасная обертка поверх legacy.

## Mitigation (практический минимум)

1. Контракты на вход/выход каждого этапа (документ + runtime-проверки).
2. Глобальные `run_id`/`story_id` и единый журнал событий.
3. Dry-run и preflight перед destructive этапами.
4. Явные publish-gates для облака/БД.
5. Пошаговое подключение модулей в оркестратор, без внутренней модификации legacy-кода.
