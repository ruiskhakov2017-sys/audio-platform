# ROADMAP

Ниже пофазный план сборки единой системы поверх существующих рабочих модулей.

## Phase 0 — Audit & Reality Map
- **Цель:** зафиксировать фактический процесс, а не предположения.
- **Входит:** карта модулей, side effects, ручные/полуручные шаги, риски.
- **Не входит:** кодовые изменения в legacy-ветках.
- **Зависимости:** доступ к репозиторию + текущим операционным практикам.
- **Риски:** пропустить скрытые ручные шаги.
- **Deliverable:** пакет reality-документов.
- **Критерий готовности:** для каждого ключевого модуля описан контракт и границы изменений.

## Phase 1 — Contracts of Existing Modules
- **Цель:** формализовать “как безопасно вызывать legacy”.
- **Входит:** module contracts (input/output/preconditions/postconditions/failure modes).
- **Не входит:** переписывание логики модулей.
- **Зависимости:** Phase 0.
- **Риски:** контракт может не покрыть редкие runtime-сценарии.
- **Deliverable:** contract-spec docs + чек-листы preflight.
- **Критерий готовности:** каждый модуль может быть вызван оберткой по формальному контракту.

## Phase 2 — Unified Config / Logging / Status Layer
- **Цель:** создать общий управляющий слой наблюдаемости и конфигурирования.
- **Входит:** единый config, модель статусов, event-лог, `run_id/story_id`.
- **Не входит:** бизнес-логика обработки текста/медиа.
- **Зависимости:** Phase 1.
- **Риски:** несогласованность имен/путей между модулями.
- **Deliverable:** новый infra-слой оркестратора (без подключения всех модулей).
- **Критерий готовности:** любой запуск фиксируется единообразно и воспроизводимо.

## Phase 3 — Safe Orchestrator MVP
- **Цель:** минимальный оркестратор с dry-run и контролируемым запуском этапов.
- **Входит:** CLI-entrypoint, wrappers/facades, step runner, preflight checks.
- **Не входит:** расширенный scheduler и глубокий параллелизм.
- **Зависимости:** Phase 2.
- **Риски:** неправильная обвязка destructive-этапов.
- **Deliverable:** рабочий MVP-оркестратор для ограниченного набора шагов.
- **Критерий готовности:** можно безопасно прогнать сценарий с dry-run и частично с real-run.

## Phase 4 — Site Pipeline Assembly
- **Цель:** собрать стабильный E2E-путь для сайта.
- **Входит:** routing в site-ветку, orchestration последовательности clean -> metadata -> audio -> package -> publish.
- **Не входит:** изменение бизнес-логики внутри модулей.
- **Зависимости:** Phase 3 + рабочие credentials.
- **Риски:** частично завершенные публикации, дубли, ошибки архивации.
- **Deliverable:** воспроизводимый site flow с status-tracking.
- **Критерий готовности:** пилотная партия историй проходит до публикации под контролем оркестратора.

## Phase 5 — YouTube Pipeline Assembly
- **Цель:** собрать E2E-путь YouTube от отбора до видео.
- **Входит:** orchestration: selection -> safe text -> director -> frames -> audio -> video.
- **Не входит:** переработка промптов или движков генерации.
- **Зависимости:** Phase 3 + доступ к Gemini/ComfyUI/RunPod/ElevenLabs.
- **Риски:** лимиты API, long-running job failures, высокая стоимость ошибок.
- **Deliverable:** управляемый YouTube pipeline с resume/checkpoints.
- **Критерий готовности:** серия пилотов дает стабильный ролик end-to-end.

## Phase 6 — Publishing Hardening
- **Цель:** сделать публикацию предсказуемой и безопасной.
- **Входит:** publish-gates, идемпотентность, post-publish verify, orphan control.
- **Не входит:** новый publishing backend.
- **Зависимости:** Phase 4/5.
- **Риски:** race conditions при повторных запусках.
- **Deliverable:** hardened delivery layer.
- **Критерий готовности:** ошибки публикации корректно детектируются и восстанавливаются.

## Phase 7 — Scale / Retry / Resume / Monitoring / Telegram Branch
- **Цель:** масштабирование и расширение каналов.
- **Входит:** глобальные retry policies, мониторинг, очереди/батчи, Telegram ветка как policy-target.
- **Не входит:** полный реинжиниринг legacy-ядра.
- **Зависимости:** все предыдущие фазы.
- **Риски:** рост операционной сложности.
- **Deliverable:** масштабируемый multi-branch прод-контур.
- **Критерий готовности:** система стабильно обрабатывает большие батчи и поддерживает multi-channel output.
