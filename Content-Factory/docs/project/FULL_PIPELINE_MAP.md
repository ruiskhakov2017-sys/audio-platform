# FULL PIPELINE MAP

## End-to-end карта производственного процесса

Ниже карта не только того, что явно есть в коде, но и фактической производственной логики (включая ручные и полуавтоматические участки).

## Stage 0. Intake (сырой массив)
- Источник: большой пул сырых рассказов.
- Состояние данных: неочищенные тексты разного качества и длины.

## Stage 1. Technical Pre-Filter (дешевый отсев)
- Цель: не отправлять мусор в дорогие LLM/генеративные этапы.
- Критерии: длина текста, число слов, грубая оценка потенциального хронометража.
- Выход: shortlist кандидатов для следующего этапа.

## Stage 2. Quality Selection via Gemini
- Цель: отсеять слабые истории и выделить годный материал.
- Каналы оценки:
  - пригодность для сайта;
  - пригодность для YouTube;
  - top-tier для YouTube-ветки.
- Текущая реализация: Gemini-автоматизация с несколькими аккаунтами и параллелью.

## Stage 3. Story Unit Formation
- Цель: превратить каждый прошедший текст в отдельный объект обработки (story-папка).
- В story-unit фиксируются:
  - source/clean текст;
  - metadata (`info.txt` и др.);
  - voice-маркировка;
  - visual данные;
  - артефакты этапов (аудио/кадры/видео).

## Stage 4. Text Cleaning and Normalization
- Цель: привести текст к clean TTS-ready виду.
- Действия: удаление мусора, дублей, артефактов, нормализация пунктуации/пробелов.
- База: `bulk-text-cleaner` + дополнительные шаги внутри отдельных веток.

## Stage 5. Metadata Generation
- Цель: получить полную служебную упаковку истории.
- Поля: title/alt-title, жанры, теги, описание, параметры голоса (`M/F/U`), доп. флаги.
- База: `Gemini_Auto` и related ветки.

## Stage 6. Branching

### 6A. Site Branch
1. Проверенная история.
2. Очистка и metadata.
3. Выбор voice и генерация аудио (`ElevenLabs`).
4. Подготовка визуала/обложки.
5. Сведение артефактов (`content_combiner`).
6. Публикация (`autopublisher`): облако + БД.
7. Архивация и учет статусов.

### 6B. YouTube Branch
1. Отбор сильных историй (`Отбор для YouTube`).
2. Safe-переработка текста (`Озвучка для YouTube`).
3. Опционально promo-вставки.
4. Подготовка текста под озвучку.
5. Режиссерский этап (`Режиссер 2.0`):
   - персонажи;
   - сцены/чанки;
   - промпты;
   - генерация кадров.
6. Озвучка (`ElevenLabs`).
7. Видео-сборка (`AutoVideo`).
8. Готовый ролик для публикации.

### 6C. Telegram Branch (потенциальная)
- Возможный выпуск альтернативной версии текста/медиа.
- Логика пока архитектурно предполагается, но как единый pipeline не зафиксирована.

## Stage 7. Publish/Delivery Control
- Проверка готовности артефактов.
- Контроль статусов, ретраев, ошибок и частичных прогонов.
- Финальная публикация и аудит целостности.

## Ключевые переходы данных (high-level contracts)
- `raw_text` -> `clean_text`
- `clean_text` -> `info/metadata`
- `metadata + clean_text` -> `audio`
- `story + scene prompts` -> `frames`
- `audio + frames/images` -> `video`
- `story bundle` -> `cloud + DB record`

## Где оркестрация критична
- единый tracking статусов между разными модулями;
- безопасный запуск destructive этапов (`delete/move/upload`);
- dry-run для проверки связности без фактической записи/удаления;
- resume и retry на уровне всей цепочки, а не только отдельных скриптов.
